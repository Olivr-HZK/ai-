> 2026-11-04已按用户要求停用此模式及来源表创建草稿入口。当前使用[主表独立复刻](replica-main-table.md)，每行一个需求、一个返回结果，不绑定需求池。以下为历史设计与任务证据，保留记录，不作为当前启动说明。

[打开需求池](https://scnmrtumk0zm.feishu.cn/base/Adz4bj9ECaCCJrsgkj7coheYn3c?table=tblKXqqPOYqk3XPd&view=vewBQwRBO3)。它与“广大大竞品”在同一Base，`关联原素材`是实际单向关联；一条需求对应一条原素材，同一素材可以建多条独立需求。

## 填写与手动启动

可以直接在第一张“广大大竞品”表的[创建复刻需求视图](https://scnmrtumk0zm.feishu.cn/base/Adz4bj9ECaCCJrsgkj7coheYn3c?table=tblwhAqPfQoBXK3Q&view=vewlY9ngR5)操作：选择`复刻需求类型`，翻译填写一个`复刻目标语言`，人物需求添加`复刻人物参考图`，然后勾选`创建复刻需求`。监听器创建默认“新建”的草稿并自动关联该行原素材；完成后清除勾选，`已建复刻需求`可打开对应草稿，`需求创建说明`显示实际结果。参数缺失保留勾选和提示，补齐后才创建。人物需求可以建草稿，实际生成功能仍受下述能力限制。

入口当前使用表内勾选项，原生按钮配置面板未能稳定保存。标识列在入口视图隐藏。相同素材可再次勾选创建另一条独立需求；单次勾选的领取、创建和回填均先持久化，未知回执仅按唯一入口标识核对，不重复建单。入口只新增草稿及来源表内新加的入口字段，不操作Replica或修改原素材附件；草稿改为“已验收”才授权执行。

1. 新建需求，填写名称、关联原素材和需求类型：替换logo、替换语言、替换人物。
2. 需求状态按用户确认保留五项：新建 → 修改中 → 已完成 → 已验收 → 结果返回。前四项由需求方维护，**只有已验收才授权执行**；已完成表示需求信息准备完毕，不表示已经生成视频。
3. 替换语言每条选一个目标语言，多语言分别建需求；替换人物上传人物参考图；Logo默认Afizzy。处理来源默认原素材，也可明确选择素材表已有的唯一复刻结果。
4. 执行器校验、领取已验收需求，依次上传自动分析、执行对应动作、下载并完整核验，结果写本需求的`复刻结果`。核验远端附件token/名称/大小后，系统才改为结果返回。

执行进度与需求状态分开，记录上传中、分析中、复刻中、下载回填中、完成、失败及需人工处理。原广告主、类型、语言、日期和原附件为领取时的来源快照；点关联记录可以查看原表完整信息。原表原附件和历史复刻附件不被覆盖。

## 当前支持范围

- 视频替换logo：沿现有CLI的智能Logo、平台默认模型与品牌参数。2026-11-04实站设置返回available=false，原因是服务端未配置腾讯云MPS；因此原任务分析后等待处理，没有提交Logo生成。自定义品牌暂须先配置对应Logo素材。
- 视频替换语言：CLI沿原视频路线，每条一个目标语言。2026-11-04实测切换原视频的PUT返回403；用户随后授权直接POST翻译，返回400，提示腾讯云MPS凭据未配置。没有生成成品，不据离线模拟宣称线上可用。
- 替换人物：字段已提供，执行器会如实标为需人工处理。设备令牌的参考图上传接口现返回403，视频人物替换未实现/验收，不能通过该选项冒充成功。
- 图片：仍使用聊天中手动触发的内置图片生成流程，不把图片当作Replica视频上传。

已接受的请求参数和源附件身份被冻结。处理后修改需求、关联或原附件会停止新增动作；需要新的版本时新建需求。反复切换已验收不会重复提交已领取记录。未知上传/生成只按原ID核对，下载临时失败退避重试，Logo/翻译明确失败不自动重新生成。飞书附件或写入回执未知沿发送记录核对，不盲目重放。

服务端明确返回403“命令行令牌不能使用这个接口”时，仅将对应需求标为需人工处理，其余需求继续。令牌失效、账号变化及其他权限错误仍停止提交并同步真实失败状态。飞书读取返回1254607（Data not ready）时有限重试，持续异常进入已有退避；业务写入不套用读取重试。

平台声明Logo不可用时，对应需求标为需人工处理并保留服务端原因，监听器继续等待其他需求，不提交生成。已阻塞需求不会因反复切换已验收自动重做；恢复服务后应核对原任务和原意图再续接。

2026-11-04用户进一步授权跳过PUT直接提交原日语需求：实际仅一次POST翻译，返回400，提示视频翻译未配置腾讯云MPS凭据，未进入生成；该次没有返回403。回执已保存为rejected，需求池说明已读回一致。尚不能根据配置检查失败断言服务恢复后是否必须切换原视频，保留原PUT和直接POST两份独立证据，不自动重试付费请求。

## 执行器

配置：`config/replica_request_pool.json`。实际目标表ID、字段ID、触发状态及Replica账号被固定。当前按用户要求在本机MacBook运行，使用本机已批准的设备令牌，每轮结束空闲等待15秒，实际周期还包括飞书读写和任务处理耗时。来源表入口通过服务端筛选只查询勾选记录。Mac mini隔离部署保留待用，本轮待批准登录已停止，远端监听保持关闭。采集/筛选/入表结束后不自动创建或批准需求。

```sh
.venv/bin/python -m ua_workflows.replica_request_pool plan
.venv/bin/python -m ua_workflows.replica_request_pool watch --background --run-dir data/request-pool-worker
.venv/bin/python -m ua_workflows.replica_request_pool status --run-dir data/request-pool-worker
.venv/bin/python -m ua_workflows.replica_request_pool pause --run-dir data/request-pool-worker
```

`plan`只读列出已验收记录，不提交。监听器等待手动状态变更，没有日历自动复刻；启动后的内部处理沿现有三个I/O通道，持续提交、完成即推进，处理并发交给后端。暂停只停止领取新操作并等待在途回执落盘，不承诺取消云端已运行任务。

验收使用假令牌/内存HTTP适配器和离线Feishu模拟验证状态闸口、Logo/翻译路由、结果只写需求池、输入变更停止、未知执行标识不重放及重复验收幂等。真实建表/关联字段读回与Mock分开留证；没有据此声称新令牌的付费POST已经实站闭环。
