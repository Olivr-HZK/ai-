# 小红书关键词采集接入

## 2026-10-27 最新容错规则（用户常规授权，后续新批）

用户要求大部分关键词成功就继续、原素材获取失败或下载中断各最多尝试三次后跳过。新批在`run.json.continuation_policy`固定`majority_keywords_media_three_attempts_v1`，规则来自配置：7词均正常尝试，至少4词真实到接口末页即允许使用已取得结果继续日期筛选、实际审核和排名。其他关键词保留失败/未末页状态与已成功页，原summary仍incomplete，collection_status=partial；日报标明成功词数、未完成词及排名仅基于已获数据。少于4词完整成功仍停止。搜索POST防重不变，已有job_id只GET，失败或未知搜索提交不自动重发。

新批原视频详情获取最多3次，含首次、失败及收费结果未知的请求。每次拥有独立意图/原响应/诊断，接电与自有防睡眠断言在提交前核验，付费详情串行。中断后原次数累计，已成功响应优先恢复，不重发已成功请求；第三次后不再新增POST。此常规授权不把搜索失败也变为三次重提。

原媒体下载/校验流程每篇最多3轮，成功文件与有实体/哈希证据的字节断点复用，不要求每轮重下载已成功文件。每轮意图和失败诊断持久化到`media/<ID>/retry-media/`；详情对应`retry-detail/`。3轮仍无法取得完整原素材则自动单列“未审核／媒体获取失败”，从可审核排名集合排除，继续其他素材；图文缺原图时整篇单列，不能伪造缺图审核。现有可用manifest与审核的哈希不符仍阻塞，不能用跳过机制隐藏篡改。待审核、未实际看图、缺主体审核证据均不能当作获取失败跳过。

次数与原run、原笔记ID、来源地址哈希及规则绑定，并受文件锁保护；恢复不清零，不另建日目录绕过预算。`unavailable-media-after-three-attempts.json`保留实际3次失败或未知证据，图片和视频均适用。媒体部分可用与搜索是否完整分别记录，日报始终如实标记部分完成，不以表同步成功冒充采集全部完成。该规则只固定到后续新run；历史scope和已完成回执不重算、不补重试、不改表或重发。

用户已选择5分钟原视频上限，后续新run在`run.json.video_duration_filter`固定`video_stream_duration_max300_v1`、max_seconds=300。300秒含可继续，超过300秒直接按时长排除，不纳入主体审核及点赞排名。必须依据实际原视频首视频流的ffprobe duration或duration_ts/time_base，不能按标题、音轨或容器总时长猜测；缺少可验证视频流时长不能当0。取得原文件并读取流时长后，超限项在完整FFmpeg解码和六帧提取之前退出，不消耗后续失败重试；不会因内容时长超限而重复获取三次。原视频尚未取得时不能声称已按实际时长排除。

每条保存原视频SHA256/大小、原始probe及其哈希、原run哈希、固定阈值、实际时长和判断，汇总到`excluded-over-duration.json`；恢复复核证据，已有文件或probe被改动仍阻塞。时长排除属于正常内容范围筛选，与媒体三次失败/未审核分开计数；日报列出5分钟上限及排除数。未查看的超限视频不写虚构主体审核。旧run无该字段继续原范围，已完成批次不重算、不改表、不重发。

阈值依据：20261027目标日批次563条已取得视频按真实视频流时长统计，P95=260.866667秒（约4分21秒），中位数23.033333秒；5分钟上限会排除23条，其中男性主体合格3条。证据`data/xhs_daily/20261027/runtime/video-duration-distribution.json`；4条无原视频不计入时长统计。另用5分03秒原视频实测六帧提取7.58秒，不含下载和主体审核；本统计不更改当日已交付结果。

## 2026-10-22：持久化异步搜索、媒体续传和电源预检

日采集搜索统一使用 `mode=async`，每个关键词/页先落盘提交意图，再只提交一次。小红书证据位于 `keywords/序号/pages/页码.job/`；抖音新批位于 `search/序号/`。`job-intent.json` 绑定业务参数、实际提交时间和地址指纹；`submit-response.json` 保留原始 job_id/费用；`job-state.json`、逐次 `poll-*.json` 和 `result.json` 保留真实状态与结果。JSON采用600权限、fsync和原子替换，批次/单job文件锁防并发重复提交。成功结果缓存直接复用，pending、网络中断或进程重启后只对已保存job_id做免费GET查询；没有确定提交回执时停止，不自动重发POST，明确未收费503也不会被无限重试。

同一批次恢复使用原命令加 `--run-dir <原日目录>`。每次运行等待单job最多300秒，单次查询超时30秒，尚未完成保留pending，不能据此排名或报告全部完成。小红书按真实cursor链顺序恢复，已完成页不重取；抖音仍每词一次最多50条，不增加分页。旧版无job_id且结果未知的请求继续阻塞，只有用户显式授权后才能通过恢复入口新开一次请求。时间窗口按真正提交时刻计算，不能把预检阻塞/恢复查询时间当成新的请求日期。新异步证据在排名前重新核验job_id、状态及业务作用域；此前真实响应和完成批次不自动迁移/重跑。

两平台CDN下载共用 `resumable_media.py`：默认64KB分段，传输错误时代理/直连各一次并逐级缩小至8KB；优先复用已成功的路径。逐段核对206、Content-Range、长度、远端文件标识及SHA256，确认落盘后才推进checkpoint。`.part` 与 `.transfer.json` 支持进程重启恢复，未提交尾部截断；已有分段哈希不符则阻塞，源URL/ETag/Last-Modified变化时保留旧断点后从头开始，不混拼文件。无远端校验标识的跨进程断点不直接信任；服务器不支持Range时改为重新完整下载并核对长度。下载完成原子改名，原图解码/视频流检查/完整FFmpeg解码仍是必需条件。资源及每跳重定向必须在平台CDN白名单内，512MB上限，不把封面或音频当视频。

抖音先依次检查搜索/已缓存详情里的video_url、download_url及明确video_bitrates，单来源最多3个不同URL，避免只因首个CDN超时就补调付费详情。付费详情仍沿用一次意图/回执缓存，不自动重调；它也执行新付费请求的电源预检。

macOS发出任何新付费搜索/详情请求前必须接电，并验证该进程自己的PreventSystemSleep与PreventUserIdleSystemSleep断言；预检期间拔电会在POST前停止。电源预检失败不生成“已经提交”的意图，接电后可安全继续。已有job_id允许只查询，不产生新付费提交；锁屏/息屏仍可继续，不修改系统电源设置。不能保证覆盖合盖、手动强制睡眠、关机或唤醒尚未启动的任务；其他系统仅记录不支持的电源预检，不宣称macOS断言已生效。

异常日志区分review_pending、async_pending、power_blocked、proxy_error、transport_timeout及media_transfer_error。等待人物/主体审核不再被归类为网络超时。API密钥、代理认证与签名URL脱敏；新代码的验证使用模拟接口/本地HTTP服务器，不实际重新采集、写表或发群。定时任务时间、平台筛选、入选数量规则及历史回执不因本次升级自动变化。

## 媒体下载和大附件兼容

2026-10-21：媒体 CDN 发生代理连接、直连超时或响应中断时，每个探测/分段/图片请求最多尝试代理、直连各一次。视频大分段两种路径均失败时，回退原URL的8KB精确分段；仍逐段核对Content-Range与长度，小分段两次失败即停止并保留断点。请求使用 identity 编码，整图 GET 核对 Content-Length 后才原子落盘。此传输重试不重发关键词搜索或付费详情 API。域名必须精确属于受信 CDN 或其子域。

媒体GET携带小红书Referer和常规User-Agent；实际验证某些原图CDN默认请求返回405，带正确来源头后同URL返回200，无需修改链接或额外付费详情。大于20MB的附件使用飞书官方media upload_prepare / upload_part / upload_finish，按服务端返回的block_size与block_num逐片上传、校验Adler32，保存每片及最终file_token回执；小附件继续upload_all。重跑先校验已有媒体SHA256及上传缓存，已匹配远端字段/附件的记录不重复更新。

## 人物图片审核（2026-10-20新增）
