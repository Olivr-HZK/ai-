# 广大大 · 页面媒体下载 v1.15.0（测试版）

本版已打包供用户测试，98项离线测试通过；未打开浏览器、未做Chrome或实站验收、未更新飞书或重载已安装插件。历史v1.14.1安装包不包含下面的续采功能。

## 暂停与继续采集（v1.15.0 测试版）

只对本版新建的「自动翻页」任务建立续采断点：保存可见筛选／搜索／排序、原日期下限、页数或末页设置、已处理页的有序广告ID、当前页身份与已经获取的地址。关闭弹窗不暂停；可以点击「暂停采集，保留断点」，页面加载超时、掉线、验证、详情异常或身份变化也会进入「采集已暂停」，不会把它记成日期截止或已到末页，不会自动跳过卡住页或启动本批媒体下载。

1. 页面恢复后，在任务列表选择原任务，恢复原筛选条件和排序，打开提示的页码，等卡片加载完成并关闭详情。
2. 点击「继续采集」。插件先只读核对筛选、页码和有序广告ID，再沿用原任务及原设置继续；已完成页不重复采集，当前页已保存的同一广告地址和已核验日期保留。可以在核对后使用新的广大大标签页恢复。
3. 上次下一页动作是否成功不确定时，不自动再点击。若页面仍停在旧页，会提示手动打开指定的下一页；不能跳过尚未处理的页，也不能混入改变后的素材列表。
4. 若决定只要目前收集的部分，点击「结束采集并下载已有地址」。本任务随后只下载已保存且日期核验通过的地址，生成一个ZIP和MD；此操作结束该任务的续采，后续页需新建任务。即使没有可下载地址也可结束，保留MD而不生成空ZIP。
5. 「停止任务」是最终停止，不能用「继续采集」恢复；已存地址仍可另建下载重试任务。暂停时可切换筛选采集另一批，恢复旧任务前必须先还原旧条件，且同一时间只允许一个任务采集地址。其他任务正在进行的媒体下载不受暂停影响。

断点保存在同一扩展的本机存储中，重启后已暂停任务仍等待手动继续。采集执行环境在详情／日期读取中重启时会暂停，避免盲目重新点击详情；已有的安全翻页等待仍按持久化阶段恢复。媒体文件字节不支持跨重启续传。MD记录暂停原因、已处理页、恢复位置与恢复次数，已观察到的半页不冒充处理完成。

旧任务缺少原筛选和页身份断点，不能事后可靠恢复，保持其已有地址与报告；需要补采时另建任务。当前页下载和跨页手动点选继续原有行为，不增加自动翻页续采。

## 安装与更新

在 Chrome 打开 `chrome://extensions`，开启「开发者模式」，点击「加载未打包的扩展程序」，选择包含 manifest.json 的插件文件夹。
已安装时，先解压ZIP并覆盖原插件文件夹内容，在扩展页点击「重新加载」，确认版本为1.15.0。当前为用户测试包，尚未做浏览器验收。请等当前下载任务结束后更新；重新加载扩展会中断正在进行的媒体传输。旧单任务清单会原样迁移到任务列表，已保存地址、选择、素材信息和失败原因保留；媒体临时字节不能跨重载续传。

## 翻页途中详情关闭与短暂读取修复（v1.14.1）

修复选择「一直采到末页」后，补读视频外链／日期详情导致采集在中途结束的两类问题：原先详情关闭仅观察约2秒，现在身份匹配后只正常点击一次关闭，最长15秒观察它是否真正消失；保留在DOM但已经隐藏的详情不再误判为仍打开。不会关闭其他广告ID的详情，也不会强制删除网页弹窗。超过等待时间仍未关闭会明确记录DETAIL_CLOSE_TIMEOUT，不冒充日期截止或末页。

Chrome短暂未返回只读页面结果时，最多尝试5次，每次间隔250毫秒；正常点击、打开详情、关闭详情和下一页动作不因未知返回值被重复执行。关闭动作如果没有拿到返回值，只观察是否已经关闭，不再次点击。登录失效、验证码和身份不符不会用重试绕过。

日期核验和详情补读的耗时不再计入本页原媒体地址加载的60秒预算；报告新增具体失败动作、脚本、页码、广告ID和关闭等待诊断。页码、卡片身份、排序、日期当天保留、单ZIP、任务隔离和已存地址下载规则保持。

此前已中断任务的地址和报告仍保留，本次更新不会自动补出未访问页面；待原任务结束后更新，再从需要补采的位置新建采集任务。

## 独立下载任务与队列（v1.14.0）

1. 可先填写「新任务名称」，再提交当前页、跨页已选或自动翻页任务。
2. 等这批显示「地址已保存」并进入下载、等待授权或排队后，就可以在广大大列表翻页、更换筛选，选择下一批。
3. 若要从空清单开始，点击「清空清单并选择下一批」；旧任务已保存的选择和地址不会被清空。原「跨页点选素材」仍继续当前选择草稿，不会自动混入其他任务。
4. 第二批保存地址后进入下载队列；前一下载结束后自动开始。允许一批采集地址、一批下载；每次只有一个任务写媒体 ZIP，该任务内最多三项并发，避免多个大包争抢磁盘和下载带宽。
5. 顶部「下载任务」可切换查看每批进度。停止、重新下载、补下载失败项和查看报告只作用于选中的任务。重下和补下载会创建关联的新任务，原任务、原 ZIP 和报告保留。

每个任务各出一个 ZIP，含自身媒体及一份 MD；不是把所有任务合成一个总包。任务名和任务编号写入 MD；已打开的报告固定到对应任务，之后创建或切换任务也不会换成其他批报告。任务之间独立去重，不跨任务替换来源。

仍在自动翻页／读取详情时不能新建另一地址采集任务，须等「采集地址」阶段结束，防止两个采集过程同时操作列表。后台下载过程中可关闭或离开原广大大页；保存地址不保证 CDN 永不过期，过期或访问限制仍逐项报告。

关闭弹窗后队列继续。浏览器退出或扩展重载后，任务和待下载队列保留；正在传输的那批可能显示中断，需要选中后重试已存地址，未开始的队列自动继续。已下载媒体字节不跨重启续传。按原目录覆盖更新才能继承同一扩展的任务；另装到不同目录通常是新扩展，不共享历史记录。

## 随下载保存素材信息（v1.13.0）

直接从每张列表卡片读取 **App／广告主名称、平台、展示估值和重投标签**，无需为这些字段逐张打开详情。不使用页面搜索关键词推断 App 归属；名称取卡片头部的可见应用名称，平台取 Google Play／App Store 图标。若卡片或已打开详情有明确商店／广告主链接，同时保存 App ID；没有可见 ID 就标缺失，不猜测。

展示估值保留页面原文（例如 `4.7K`），同时记录换算数 `4700` 和“近似”标记；K、M、万、亿属于页面缩写，并非精确原始计数。页面显示 `0` 则保留为 0。重投只依据明确可见的“重投／非重投”标签，未见标签记为“未知”，不把它当成非重投。

这些字段与已选素材的原页码、从左到右编号、广告 ID 和下载文件一起持久保存。本页全部、跨页点选和自动翻页均支持；列表重绘、返回原页或后续缺字段不会抹掉已存信息，出现字段冲突会明确提示。采集地址／日期时如已经正常打开并核对了该广告详情，也保留其中明确显示的信息；不会为了补素材信息单独点开详情，不新增地区采集。

ZIP 中仍是媒体文件和唯一一份 `下载报告.md`。报告新增「素材信息」表，包含名称、App ID（可见时）、平台、展示估值原文／换算数、重投标签、来源与缺失原因，以及对应结果和文件路径。成功、请求失败、缺址、重复合并、类型未选和日期跳过的选择都有记录，元数据缺失不阻止已存媒体地址下载。账号被挤下线后仍使用已存字段和 CDN 地址下载，失败补下载也保留已存信息。

**旧版任务、旧清单或已经生成的 ZIP 不会凭空补出这些字段。** 升级后重新采集／点选才能保存新的列表信息；仅重试旧地址仍会注明信息缺失。报告不导出原媒体签名链接、账号凭据、整份卡片绑定对象或页面原始全文。

## 大批量写入本机磁盘与失败补下载（v1.12.0）

保留「先采集并保存地址，再统一下载」的两阶段流程。媒体下载时分块写入本机临时磁盘，最多三项同时下载；完成的文件逐个写入同一个ZIP并释放该文件的临时副本，不再把整批媒体攒在内存里。取消旧版整批512MiB上限，单个文件也可超过512MiB；ZIP支持ZIP64，容量仍受本机可用磁盘空间、浏览器和目标文件系统限制。一个ZIP内仍只有成功媒体和一份`下载报告.md`。

升级后可点击「补下载失败项」：若原ZIP已保存，只重试原批失败且已存地址的素材，不再下载原包成功文件；若原ZIP未成功交付，则重新获取本批全部已存地址，避免遗漏已获取但未保存的文件。保留原页码和卡片编号，不重新登录、采集或翻页；补下载ZIP有新文件名，原ZIP保留。MD说明原包、已交付数量及本次逐项结果。缺少地址的素材需回到原页重新采集，外链解析限制不会因换成磁盘写入而消失。

临时文件由扩展私有存储管理。完成保存、停止或失败后自动清理；浏览器/插件异常退出的残留会在下次下载任务开始时清理。下载期间请预留“临时ZIP + 最多三个正在下载的文件 + 最终ZIP”的空间，通常至少是素材总大小的两倍再加正在下载文件所需空间；磁盘不足或读写失败会停止并在MD中明确说明，不交付不完整ZIP。关闭弹窗可继续；退出浏览器或重新加载扩展会中断本批，媒体字节暂不跨重启续传，可用已存地址重试。

新增Chrome的`unlimitedStorage`权限，用于扩展本机临时文件的存储配额；它不提供无限硬盘空间，也不新增媒体站点访问范围。仍仅在实际出现新媒体来源时申请该站点权限。官方依据：[扩展存储](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)、[磁盘文件流](https://web.dev/articles/origin-private-file-system?hl=en)。

## 翻页重绘等待修复（v1.11.1）

v1.11.0 在页码或卡片身份的一次读回不一致时，会立即中断采集并按已存地址下载；这可能使尚未到达日期边界的任务提前结束。v1.11.1 将下一页卡片稳定观察延长为2秒，识别骨架加载；当前页卡片短暂消失、重建或相邻页码标签短暂不一致时，最多等待15秒恢复原身份，不在等待期间点击、翻页或读取不匹配卡片。

点击下一页之前重新核验已采页面；若页面脚本明确表示因重绘而尚未点击，会返回原等待状态，恢复后只点击一次。网络或脚本通信失败导致点击结果不确定时不盲目重点击。持续变化、远距离跳页、离开原列表、登录或日期核验失败时，新建可续采任务暂停保留断点；旧任务仍沿用已有地址下载的行为。

弹窗和MD报告明确区分「日期截止」「列表末页」「页数上限」「采集提前中断」。报告记录等待恢复次数、检查阶段/动作、期望与实际页码/卡片数量、首个不同位置与广告ID、等待耗时；中断不能当成已经采到设定日期。旧任务的泛化错误无法补回未记录的具体期望/实际页面，不把模拟故障来源当作该次实站根因。

## 首次发现日期自动截止（v1.11.0）

1. 先在广大大列表选择「最新创意」，保持从新到旧的顺序。
2. 插件「采集范围」选择「自动翻页（每页全部）」，勾选「按首次发现日期自动停止」。
3. 设置「最早日期（含当天）」。例如填写 `2026-10-22`，保留22日及之后的素材；遇到第一张21日或更早的素材时，停止本页后续采集与翻页，该素材也不下载。
4. 可以同时输入页数上限或选择一直采到末页；页数、末页和日期截止中，先到的生效。日期选项会保存在本机，关闭弹窗后仍能恢复。

日期口径为卡片或对应详情**可见日期范围的起始日期**。卡片缺少唯一、有效日期范围时，只正常打开该卡详情并核对广告ID后补读；独立「首次发现 (UTC+8)」旧字段、重投标签、网站日期搜索框和未核对的绑定时间戳不代替此口径。列表排序无法确认为「最新创意」时拒绝开始；采集中排序发生变化即停止继续采集。

所有已观察地址仍先保存在本机，只有日期已核验且在截止前的素材才进入下载队列。日期无法读取、详情身份不符或账号中断时，新建可续采任务暂停，等待继续或明确结束采集；旧任务保留原下载行为。尚未核验日期的地址不会混入ZIP。主动点击停止不会自动下载。重新下载只使用上批日期已通过的保存地址，不继续翻页。

同一份 `下载报告.md` 新增日期下限、截止页码/原卡片编号/广告ID/日期，以及「日期未纳入」「日期未核验」记录。因日期跳过不算媒体请求失败；截止页后续位置和未访问页面不冒充已采集到末页。若第一张卡片即超过日期边界，本批只保留可查看/保存的MD报告，不生成空ZIP。

此日期截止只用于自动翻页，本页下载和跨页手动已选清单仍按用户实际选择下载。未勾选日期选项时保持原翻页行为。

## 先保存地址，再统一下载（v1.10.0）

本页、跨页已选和自动翻页统一分成两个阶段：

1. **采集并保存地址**：先保存全部已确认选择及列表已有的图片、视频、Playable地址；启用日期截止时先核验日期、只将范围内素材排入下载；缺址视频再逐个补读详情。每读到一条新地址就写入本机 Chrome 扩展存储，完成保存后才关闭详情、操作下一卡或翻页。跨页点选同样先保存选择和已有地址，再补读详情。
2. **按已保存地址下载**：地址采集结束后才启动插件下载队列，统一生成一个 ZIP。下载阶段不再读取广大大列表，也不检查广大大账号是否在线。

账号被其他设备挤下线、登录过期、验证拦截或翻页异常时，新建自动翻页任务暂停并保留断点，等待继续或明确结束后下载；旧任务、本页和跨页手动选择保留原来的部分地址下载行为。报告注明采集中断原因和范围；未取得地址的已选素材单列，未访问的后续页不虚构卡片名单或宣称采到末页。有一项成功即与报告合为一个ZIP；全部失败或一个地址也没有时保留可查看/保存的MD报告，不生成空ZIP。

「重新下载已存地址」只使用本批保存的地址重新下载，无需重新打开或登录广大大；不会重采后续页面。暂停的自动翻页任务要补采应使用「继续采集」；已结束或旧任务需要另建任务。地址清单是本机内部保存，不额外下载JSON或把签名链接写入MD报告；每批任务的MD独立保留。

关闭弹窗不影响任务；明确点击「停止任务」会停止，保留已存地址而不会自动转入下载。地址采集中的扩展执行环境重启后，可用已保存的清单继续下载；浏览器退出后不保留已获取的媒体字节，重新下载会重新请求文件。CDN失效、签名过期、媒体站点访问权限以及YouTube签名/分离流等限制仍按实际结果报告。

## 自动尝试补全视频外链（v1.9.0，v1.9.1 修复详情外链漏读）

v1.9.1 修复列表没有原地址、但详情存在 YouTube 原始链接的漏读：只对缺址或缺少完整ID且无可用备用地址的视频，按卡片正常打开详情，核对广告ID后读取明确的原始媒体链接，再关闭插件打开的详情。跨页点选时会先读取并保存详情外链；下载本页和自动翻页也会补读。请在详情读取完成后再翻页。已有旧清单中的当前页缺址项可在新建打包时补读；其他页的旧缺址项需要返回对应页重新点选。关闭自动补全后，新建下载不会自动打开详情。

此修复解决“有外链却被判缺少原地址”，读取到 YouTube 链接仍不等于一定能下载；平台签名、登录和分离流限制仍按实际结果写入报告。

默认勾选「自动尝试补全视频外链」，本页、跨页点选和自动翻页均生效。仍按每张卡片一个主要素材获取，成功文件与图片、Playable合并为一个素材ZIP，不单独生成外链文件包。

- 优先获取原视频；失败时尝试同一张卡片提供的其他视频原址。备用来源限视频字段、明确的视频CDN/下载地址，以及该卡片提供或可见的YouTube链接；不把广告落地页、封面、应用图标当成视频。
- 外链返回网页时，仅静态读取`video/source`、视频元数据和`VideoObject.contentUrl`，可识别YouTube嵌入链接。不执行外链脚本、不点击安装链接、不调用平台私有接口、不填写登录或处理验证。
- YouTube的watch、youtu.be、embed、shorts、live等链接统一为同一个完整视频ID。只尝试公开网页中已提供的、无需播放器签名处理的音视频合流地址；核对视频ID并检查返回内容的媒体文件头。ID残缺时不猜测补齐；不同广告共用残缺链接前缀不会因此合并。
- **不保证所有YouTube或其他平台外链都能下载。** 需要签名处理、登录/验证、DRM、仅有分离音视频流或HLS/DASH时仍会失败，报告说明原因；不会把静音的视频流冒充完整YouTube视频。纯插件不安装本机辅助服务或调用第三方解析网站。
- 每项最多尝试8个地址、网页嵌套最多两层、单个解析网页最多8MB；每项所有实际网络步骤共用120秒预算，等待站点授权期间暂停计时。若解析发现新的素材站点，暂停至「授权并继续打包ZIP」，只申请实际站点，保留已获取文件；关闭弹窗不会重取这些文件。

同一份`下载报告.md`新增「视频外链自动补全」区，逐项记录尝试来源、站点、结果和失败原因，成功项注明补全成功；不导出签名URL或凭据。整批失败也可从插件查看并保存报告。取消勾选时只按原地址直接获取，不进行外链解析或备用地址尝试。

## Playable 试玩原 HTML 获取

「图片」「视频」旁新增「Playable」，默认勾选，可单独下载或与图片/视频混合下载；当前页、跨页点选、自动指定页数和采到末页均支持。读取实际 `ads_type=7` 卡片的 `resource_urls[].html_url`，兼容该卡片 `html_url` 与明确为HTML的 `cdn_url`，不以试玩封面或视频代替HTML。

成功项保存在同一个 ZIP 的 `媒体/第XXXX页/playable/原编号_文件名.html`（原址为`.htm`时保留扩展名），原始字节不改写。获取时不执行试玩脚本、不自动访问依赖或安装链接；拒绝登录/授权页、JSON、非HTML和无脚本/画布/iframe的错误网页。缺原址、权限/HTTP失败等继续写入同一份 `下载报告.md`。

**这是原HTML获取，不是完整离线归档。** 试玩可能引用远端JS、图片、音频或动态资源，外部依赖未打包；打开HTML可能需要联网，也不能保证本地直接运行。报告记录静态检查发现的外部引用数量及此限制，不宣称离线可玩。当前不抓取Playable内部脚本资源或把HTML转换为视频，不支持原ZIP试玩包。

## 跨页点选，一起打包

1. 登录广大大，打开展示广告列表，点击插件里的「跨页点选素材」。
2. 点击卡片左上角编号勾选。编号按本页从左到右、从上到下排列，勾选不会触发详情跳转。
3. 在同一个广大大标签页使用网站正常翻页按钮，下一页会自动显示编号，继续勾选；翻回前页会恢复勾选。
4. 再打开插件，默认选择「跨页已选清单」，可看到每页所选编号及总数。
5. 点击「保存已选地址并下载 ZIP」，所有已选页面的素材只生成一个 ZIP。

页面工具栏提供「全选本页」「清空本页」「清空全部」「收起点选」。清空本页保留其他页选择；收起点选保留清单。
插件弹窗也可清空整份清单。未选择任何素材时拒绝提交，不会回退成下载全页。
同一广告素材 ID 在多个页面出现时只选择一份，并在其他页同步显示勾选；相同原链接打包时也会合并。
清单按浏览器标签页保存，刷新网页可恢复，关闭该标签页会清空；不同标签页的选择不混合。
页面加载时等待勾选恢复再操作；正在保存勾选时会暂时拦截翻页点击，避免未保存就离开本页。
打包不会自动清空清单，可以继续增减、重新打包。签名链接可能过期，失败时请返回对应页加载原素材后重新提交清单。

## 自动翻页：指定页数或直到末页

将「采集范围」切为「自动翻页（每页全部）」，再选择采集终点：

- 「输入采集页数」：手动填写页数，包含当前页，允许 1～1000 的整数；遇末页提前停止。
- 「一直采到末页」：从当前页开始逐页前进，直到网站下一页明确禁用，不受填写页数限制。

自动采集获取每页全部所选类型，已保存的点选清单保留；需要只下载挑选项时切回「跨页已选清单」。
插件通过页面分页按钮前进，核对页码递增、卡片身份、加载状态；缺原址的卡片会滚动触发加载，合并快照并等原地址稳定后收集。
采集期间保持列表标签页打开，不手动翻页、切换筛选或打开详情。关闭插件弹窗仍继续，可以重新打开查看页数进度或停止。
页面停在最后采集的页。未知分页、页码跳跃、整页重复、下一页30秒超时、每页原地址60秒超时或离开列表时，新建任务暂停并保留断点；报告明确标记范围未完成。可恢复原页后继续，也可明确结束并下载已有地址。已经结束的任务和没有断点的旧任务若要补采后续页，需新建任务。

## 一个 ZIP 与进度

「仅当前页全部」可直接打包本页。所有模式最终都只保存一个文件：默认下载目录 `广大大/广大大媒体_时间.zip`。
ZIP 使用原始媒体字节，不转码；含 `媒体/` 和一份 `下载报告.md`，不再附 JSON 或 HTML 报告。跨页模式按网站实际页码分目录，文件名前缀保留该页卡片编号。
报告分为「失败及未完成内容」「全部选择」，每项标明原页码、卡片编号、广告ID、媒体类型（含Playable）、结果、文件名、原因与处理建议。成功、请求失败、缺原址、不支持、重复合并、类型未选和停止/未执行分别统计，全部选择可逐项对账；重复项指向合并后的原页编号及文件结果。报告不包含签名链接或登录凭据。
HTTP 401/403/404/410/429/5xx、网络失败/传输中断、120秒有效网络超时、本机磁盘不足/读写失败、非媒体响应、空文件分别给出原因；403等只说明服务器证据及可能原因，不把无法确认的失败直接说成「不支持」。流清单、blob等非HTTP地址和其他未识别类型明确列为不支持；缺少或无效原地址单列，未发起下载请求。
单项获取失败时其余成功媒体入包并报告；全部失败或所有卡片均无可下载地址时不生成空包，仍持久保存本批清单与失败原因，可在插件点击「查看下载报告.md」，再按需点击「保存下载报告.md」单独保存。取消和翻页异常同样可查看报告，未采集到的后续页不会冒充已选择。插件报告页固定显示打开时选择的任务；创建下一批不会替换原任务报告。
「已获取」是保存 ZIP 前进度，只有「ZIP 已保存」表示 Chrome 下载完成。
「重新下载已存地址」重新请求本批已保存地址并生成一个新ZIP，保留采集范围未完成的说明。

首次点击下载时仅请求本批实际使用的媒体 CDN 权限；自动翻页遇到新的 CDN 时，会暂停到「授权并继续打包 ZIP」，只申请实际使用的站点。
拒绝后清单保留，可稍后继续。关闭弹窗后继续；停止取消当前批次。
打包任务在权限弹窗出现前交给后台；即使授权时插件弹窗被 Chrome 关闭，授权完成后也由后台继续，不需要靠原弹窗保持运行。

## 支持范围与限制

- 仅支持展示广告列表中实际渲染的 `.shadow-common-light.bg-white` 卡片。读取每卡 React 绑定 `value` 的 `ad_key / ads_type / resource_urls`；不读父列表、不调用网站私有接口、不扫描整页图片或浏览历史资源。
- 每卡只取一个主要原素材。视频优先取 `video_url`，开启外链补全时读取本卡备用视频原址及明确的YouTube链接；图片取 `image_url` 或该图片卡的 `preview_img_url`；Playable取原HTML。不下载应用图标、背景或视频封面，不以封面补缺失视频或试玩。
- DRM、HLS/DASH、无 HTTP 原地址和非HTML试玩包不支持，列入下载报告。
- 无旧版512MiB整批/单文件上限，仍为一个ZIP；每项有效网络时间120秒，磁盘读写、ZIP汇总与等待授权不占此网络预算。本机空间不足时明确停止，不自动拆多包。
- 媒体流式写入本机临时磁盘，浏览器退出或插件重载暂不能续传已获取的媒体字节。新建自动翻页任务的采集断点可保留；详情采集过程被中断时暂停等待核对原页，不盲目重点击。旧任务仍可按已保存地址重试下载。
- 服务器防盗链、签名过期、Cookie/SameSite 限制仍可能导致失败。无需 cookies API，不读取账号凭据，不上传媒体；HTML/JSON 错误响应不会当作媒体成功保存。
- Chrome 如果启用下载前询问位置，保存 ZIP 时可能需确认一次。
