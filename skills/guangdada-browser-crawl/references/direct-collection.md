# 默认模式：浏览器直采与并行原素材下载

2026-10-22 用户要求沿用本次实际采集方式：不依赖插件弹窗，仅参考插件的批量读取、原素材下载、去重和失败报告逻辑。使用环境授权的浏览器工具；不复制插件读取 React 内部状态的实现，不监听网络或调用广大大私有接口。

## 实际执行入口

新每日批次由prepare固定 `collection_mode=direct-browser-v1`。使用本skill的 `scripts/direct_session.mjs`，不再复制data目录中的临时脚本。它包含当前实站DOM的默认观察、综合查询、点卡、详情身份读取、分页、截图/哈希和断点适配；页面UI变更时可传`ui`适配器，但所有适配仍须从实际可见DOM读取，不能返回期望值冒充观察。

先按每日流程完成一次启动通知和BROWSER_PENDING登录证明，再在授权浏览器REPL导入：

```javascript
const {createDirectSession} = await import('/实际skill目录/scripts/direct_session.mjs');
let session = await createDirectSession({
  tab, browser, runDir: '/本批绝对目录', taskId: 'ios-01',
  projectRoot: '/项目绝对目录'
});
await session.start();       // 一次begin，组合准备；正确筛选不点击
await session.batch();       // 最多10张或45秒，返回耐久断点摘要
// 返回page_end时：await session.nextPage(); 然后继续batch()
// 返回WAITING_HUMAN时立即交人工；确认解除后await session.resume('真实用户确认')
// start返回existing_checkpoint时，读取checkpoint后继续batch；暂停状态先resume，不能重置进度。
```

`tab`和`browser`是当前已授权浏览器的现有句柄，脚本不创建浏览器/驱动。`projectRoot`用于调用既有本地Python状态命令，不发送站点请求。每个App新建session；模块内部绑定固定task，不能把旧session用于新App。一般任务或旧scope不加模式标记，继续旧批量入口，不自动迁移历史。

脚本在截止、明确零结果或实际下一页禁用后生成`direct/complete.json`，并调用 `.venv/bin/python -m ua_workflows.social_chat_direct accept --run-dir <目录> --task <任务>`。验收器重新读取准备动作、详情身份、日期、连续位置、翻页、截图哈希和封账卡片哈希，只有通过才由正式状态机进入下一个App。无需逐CATEGORY/FILTERS/APP/SORT/PROBE调用CLI。`direct/validation.json`记录实际验收耗时；`direct/batches/*.json`记录批次耗时/结果，状态机仍记录App尝试和人工等待。

本地队列直接运行 `.venv/bin/python -m ua_workflows.social_chat_direct_media prefetch --run-dir <目录> --watch`；单批文件锁拒绝重叠队列，最多3路，watch最多15分钟并在暂停/全采结束后退出。结束采集后再执行不带watch的prefetch补齐尾部。媒体准备使用同模块 `review-media --run-dir <目录>`，复用下载文件生成原有六帧/原图manifest及有限失败例外，不生成任何内容审核决定。随后仍按原规则实际查看、记录reviews、混合取前10%、入表和群日报。

## 一次完成点卡前准备

- 固定目标日、完整 App 名、App ID、系统和分类。iOS/Android 独立任务；分类以已核实任务范围为准，不把所有产品都默认归工具。已确认 Heyyyy iOS 在游戏标签有结果；若固定 scope 与实际分类冲突，先正确准备任务范围，不伪造工具下的成功或零结果。
- 当前筛选一次读回：分类、日期、素材去重、类型、渠道、地区、语言、尺寸。正确的条件只读；有残留才修正。不逐个打开空的国家/渠道控件。
- 综合搜索 → 清理旧关键词/广告主残留 → App ID → 真实 Enter → 读回唯一已提交关键词 → 点击最新创意。忽略下方广告主候选，不等待或选择候选。
- 将这些确定性操作合并在 `direct_session.mjs` 的start/prepare内。`scripts/browser_prepare_app.mjs`仅供旧模式使用。正常只返回摘要，证据保存本地；不把每个子步骤都交回模型。
- 搜索或翻页后，先确认加载结束、实际查询/页码正确且卡片集合已更新，才保存页面盘点。不能把短暂空列表、骨架屏或残留的上一 App 卡片记为零结果/本页清单。仅填写页码或按钮返回成功不足以证明页面已更新。

## 同页连续点卡

`direct-browser-v1`使用上述`direct_session.mjs`，默认每批最多10张、45秒预算，逐卡仍真实点击并保存原文、全部业务字段、前后截图和哈希。旧模式才按 [browser-batch.md](browser-batch.md) 使用`browser_batch.js`。一次正常批次只向模型返回任务、页码、完成数、下一位置、截止/错误摘要，不输出整页 AX 或每张详情全文。

1. 从当前列表确认卡片预览/“详情”实际定位，再用浏览器 locator 点击。优先可稳定点击的预览区域；工具超时后先读回详情是否已打开，不盲目再点一次。
2. 身份、广告 ID/详情 URL、日期范围、估值、媒体类型及来源就绪即保存；不等待视频播放、缓冲、AI分析和推荐区。详情名称可与商店名不同，但真实 App ID/系统不能不同。
3. 有商店链接时直接取真实 App ID/系统。仅有官网或 onelink 落地页时，点击本条详情中的 App 身份入口，核对实际打开页面的 store/os 或商店链接；保存 URL、观察时间、名称和截图。复用该已观察映射时，每条仍检查详情名称与平台，不以查询关键词充当身份，不合成不存在的商店链接。
4. 每张落盘后才移动耐久断点；保存与关闭详情分开记状态。关闭失败但卡片已保存，恢复先关闭，不重采已保存卡。
5. 只用详情可见日期范围起点：晚于目标日不入候选，等于则保存，第一张早于目标日保存为截止证据并停本 App。重投也正常点卡，全部采完后统一剔除独立重投标签。
6. 本页完毕后真实翻页，读回页码和新卡片集合；空白加载期不算末页。实际已翻页但工具报超时，先核对实际页面，再更新断点，不再次翻页。每个 App 保存完成清单后换下一个。

REPL 中复用模块/函数时，显式传入当前 `{tab, task, runDir, page, position}` 或当前 session，不能让持久闭包捕获上一个 App 的可变对象。只替换外层变量名不能证明函数使用了新任务；批次入口核对任务/页码。

## 采集与下载并行

每页/每 App 保存媒体地址后，即可把**已观察的原素材**加入本地下载队列，与之后的浏览器点卡并行；无需等21项全采完才启动下载。默认最多3个下载并发，浏览器仍单任务串行；不要并行打开多个 App 点卡来提速。

- 视频只用详情实际 `<video>/<source>` 原地址；图片只用详情已确认的原图元素，多图逐项保存。App图标、列表封面、推荐图不可当作原素材，不能靠替换后缀猜 MP4。
- 队列以任务/广告 ID/媒体序号去重；相同原地址可复用已校验下载，但每个 App/系统的业务记录仍独立。每个资源只有一个活跃下载任务。后台进程未结束不得再启动重叠队列；新页追加到该队列或等待本轮结束后再处理。
- 下载先写临时文件，检查 HTTP、内容类型、长度和非空，再验证视频流/尺寸/时长及完整解码，或图片格式/尺寸/完整解码，记录字节数和 SHA256 后原子落盘。已有校验成功且哈希一致的文件直接复用。
- 普通传输失败最多初次加一次重试；失败回执跨后续批次保留，不能每启动一轮下载又给同一失败项重置预算。403/404、授权/验证限制、地址截断等保留真实原因，不无休止重试或猜替代 URL。
- 仅对实际观察的 YouTube 原始链接使用 skill 的 yt-dlp 补全流程；按 URL 主机名识别 YouTube，不把广大大详情 URL 中的 `channel=youtube` 当作原始视频。无 cookies、无登录绕过；日志、原始来源和实际文件分开保留。下载成功仍须校验及后续抽帧。
- 试玩单独计数；仅采视频/图片时不下载试玩、不用试玩封面充图片、不计为下载失败。

下载预取不等于 MEDIA/REVIEW 完成。全量封账后，依原规则排除重投，对剩余视频真实抽六帧并查看、图片逐图查看，合并有效候选取前10%。仅下载任务输出原始下载清单，明确“未审核/未排名/未入表”，不能发送业务完成日报。

## 验证码、恢复与耗时

验证码出现立即停止浏览器操作，保存当前 App/页/下一卡、详情是否已保存/仍打开、截图和实际错误，进入人工等待并释放防睡眠保护。不能通过切 App、刷新、换浏览器或改变节奏绕过验证。已有本地媒体下载与浏览器等待分别记状态。

用户确认处理后先观察验证是否消失，再重新核对筛选、综合查询、排序、页码和最后已保存广告 ID。页面常会重置为游戏/近1年/广告；只修实际变化，恢复固定目标日，不重新计算“昨天”。必要时只读回上一张已保存广告 ID 作为边界核验，不重复落盘/下载。边界不一致时按广告 ID 对账，不能照旧位置跳过可能新插入的素材。

逐卡保存真实动作起止、读取/落盘/关闭耗时和错误；按页批量登记操作，不每卡调用状态 CLI。人工等待、筛选恢复、身份补证、下载/解码、YouTube补全分别统计，不能把首张至末张跨度当作纯点卡耗时。没有证据不声称“验证码就是因为点快”，不把规避站点验证作为提速目标。

此模式合并工具往返，不取消证据校验。新模式每日状态机以单个APP_COLLECTION_PENDING接入直采验收；后处理七个状态保留，通用/旧任务仍按原校验器执行。不能复制本次临时`direct-complete.json`或手改状态冒充通过。最终下载清单按App/系统列出成功、失败、无原始地址、范围外类型，并区分原始卡片数、唯一广告数和实际文件数。
