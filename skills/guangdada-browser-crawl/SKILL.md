# 广大大展示广告：浏览器采集与强制检查

## 支持范围

| 功能 | 范围 |
|---|---|
| 站点页面 | 广大大「展示广告」 |
| 分类 | 游戏 / 工具 |
| 渠道 | 页面实际可选渠道，按用户要求选择；不限时也须检查“全部”状态 |
| 国家/地区 | 页面实际可选国家和地区，支持多选或不限 |
| 列表模式 | 广告 / 素材，分别核对当前模式对应的卡片总数 |
| 日期 | 7天 / 30天 / 90天 / 1年（UI 可能显示“近1年”），以及自定义起止日期 |
| App | 完整 App 名、已选广告主 ID 和平台一致，iOS/Android 分任务 |

视频类型、比例、排序、语言和内容要求可按用户指令作为额外条件，不把 Tipsy、日韩、9:16 或男性角色写成通用默认值。读 [scope.example.json](references/scope.example.json) 后按本次指令修改；date 为快捷或自定义的结构，不沿用旧 time_window 字段。

使用环境提供的浏览器工具，不固定 UI 位置或旧选择器。开始前读其文档；所有站点点击和读取均在该工具内执行。无需原项目或爬虫包。

## 固定执行顺序（逐 App 串行）

登录 → 选择游戏/工具 → 填写并检查除排序栏之外的筛选 → 在搜索框输入完整 App 名并选中广告主 → 点击展示估值/热度排序并检查 → 本页逐卡 → 下一页逐卡 → 明确末页 → 写本 App 采集完成清单 → 下一个 App。

展示估值/热度属于 **App 选择后的独立排序阶段**，不能提前并进基础筛选。每个 App（含同产品不同平台）都重复此顺序。先清理旧广告主/关键词，确保基础筛选与新 App 各自检查通过。

采集完成后执行 `state.py seal --run-dir ... --task ...`，由脚本核对卡片/分页后生成本 App 的 `collection_complete.json`；`check` 同时生成总清单 `app_checklist.json`，指明 `next_collection_task`。未写完成清单，下一个 App 为 PREVIOUS_APP_PENDING，不能跳过。这里的“完成”专指该 App 原始采集；抽帧、审核、下载和交付仍独立检查，不冒充已完成。所有 App 原始采集登记后，继续这些后续关卡。

## 强制检查，不接受手填成功

先读 [browser-check.md](references/browser-check.md) 和 [state-contract.md](references/state-contract.md)。

1. **App 和全部筛选都必须通过脚本检查。** 用 `scripts/browser_check.js` 中的 gddCheckedClick 在浏览器工具 REPL 里执行真实点击、读取实际状态，保存点击前后原生 PNG/JPEG 和哈希。每个 scope.filters 字段各有一个匹配日志；基础筛选写 filters.json，排序单独写 sort.json；只说“已点击”、只保存期望值或只有截图均不能过关。
2. **每张卡片和翻页也检查。** 点卡读回真实详情身份；第2页起确认实际页码/卡片集合改变，保存 page.open 日志。缺日志、读回不符、截图缺失或哈希不符都停在对应关卡。
3. **视频必须脚本抽帧并查看截图。** 全量原始采集完成后，先下载原视频到任务目录，执行 `scripts/frames.py`，生成 3%、15%、30%、50%、70%、90% 六处真实抽帧。检查 manifest、源视频和图片哈希，再实际查看六张图，记录 frames_inspected=true 后才能完成内容筛选。无法下载/解码/抽帧的任务报告未完成，不以描述或占位图替代。
4. **审核内容与交付视频必须同源。** 保留视频哈希须等于抽帧源视频哈希。抽帧不是完整观看/审听；男角色、女频、真人口播等语义仍由 agent 按画面判断，不确定项单列待复核。

校验器只验证记录、读回值、数量、图片格式/尺寸与哈希；它不能证明截图语义或人工判断，也不是防篡改取证系统。不得手工伪造脚本日志或成功值。

## 状态机

```bash
python3 /path/to/skill/scripts/state.py init --config scope.json --run-dir runs/job-001
python3 /path/to/skill/scripts/state.py check --run-dir runs/job-001
```

| 通过关卡 | 要求 |
|---|---|
| BROWSER_READY | 当前可操作浏览器、登录成功、页面证据 |
| CATEGORY_VERIFIED | 登录后先选游戏/工具，脚本和截图检查通过 |
| BASE_FILTERS_VERIFIED | 除排序栏外各项与 scope 一致，有脚本点击读回和前后截图 |
| APP_VERIFIED | 完整名称、正确平台、唯一已选广告主、无残留关键词，脚本和截图验证 |
| SORT_VERIFIED | 选中 App 后再点击展示估值/热度，日志时间与读回值正确 |
| PROBE_PASSED | 实际点开一张详情，身份正确，成功点击日志与原始记录已落盘 |
| CRAWL_COMPLETE | 全部卡片、连续分页、逐页盘点、末页证据和数量一致 |
| APP_COLLECTION_COMPLETE | 采集核对通过，由 seal 生成完成清单，再进入下一个 App |
| FRAMES_VERIFIED | 每条原始视频六处抽帧齐全，源视频和图片校验通过 |
| REVIEW_COMPLETE | 全部素材有决定/理由/审核方法，已查看抽帧；待复核不混入保留 |
| MEDIA_COMPLETE | 保留视频全部可读、实际尺寸/时长/解码检查、与抽帧源哈希一致 |
| DELIVERY_COMPLETE | 全部文件齐全，实际打开预览，验证相对路径和媒体 |

检查返回当前 *_PENDING（含 CATEGORY_PENDING、SORT_PENDING、COLLECTION_SUMMARY_PENDING、PREVIOUS_APP_PENDING）、COLLECTING、WAITING_HUMAN、COMPLETED 或 COMPLETED_WITH_REVIEW，附 gate_failure、next_action、passed、checkpoint.next。状态由脚本计算，不能改 state.json 绕过失败。后者完成状态须披露待复核数。

脚本校验需 Python 3.10+ 标准库，真实抽帧另需 FFmpeg/ffprobe；缺依赖报告原因，不把该步视作成功。每个 run 串行写入、逐卡原子落盘，显式传任务/平台/输出路径，避免旧任务闭包串数据。

## 浏览器流程

1. 整理用户给的完整名称和平台对应关系；简称先从会话名单解析，无法确认不瞎猜另一端名称。固定查询日期与时区；滚动日期跨天恢复用已核实绝对范围或新建 run。
2. 打开展示广告，先脚本 check 游戏/工具，再设置渠道、国家、广告/素材、日期和其他基础条件；此阶段不点击排序栏。自定义日期核对开始和结束值；快捷日期核对实际选中项。首次设置、切 App、验证码恢复和 UI 重置后都重新检查 App 与全部筛选。
3. 移除旧广告主图标及残留关键词，输入完整 App 名，点击正确平台的候选；脚本读回唯一已选广告主身份。只输入文字搜索可能叠加旧 App，制造假空结果。按广告/素材当前模式记录 card_count 和 count_basis；之后点击用户指定的展示估值或热度，单独检查并写 sort.json。
4. 单卡测试通过后，逐页逐位置点开全部详情。等关键字段加载完成，确认不是上一张详情，再保存广告 ID、App身份、详情链接、媒体地址/缺失原因、渠道、地区、语言、尺寸、日期、估值和原文。字段缺失如实记 missing_fields。
5. 每张保存后才移动断点；本页齐全才封账和翻页。计数变化、跨页重复、页面未变化都需排查，不能拿最后成功页冒充末页。只有下一页明确禁用或正确 App 下明确零结果才能结束。找不到候选不等于零素材，不伪造 app_id。
6. 本 App 全量后先执行 seal，核对总清单中已完成再进入 next_collection_task，直至所有 App 原始采集登记；随后下载、脚本抽帧、查看截图并筛选。Facebook 系可能附带 Instagram/Audience Network，按详情二次排除非目标渠道。包含日韩投放不代表只投日韩，不代表文案语言或估值仅来自日韩；日期不自动加 first_seen 或排除重投条件。
7. 分平台保存，交付相对路径可播放预览及清单；需要 ZIP 或复制到指定项目时按用户要求做。最终调用 `check --require-complete`，退出码 2 表示仍未完成，必须披露失败/待复核/缺失步骤。

## 中断、变更与边界

- 遇验证码/安全验证/用户接管，停止点卡，执行 `state.py hold --run-dir ... --task ... --reason captcha --cursor 'page=2,next_position=23'`；请用户手动完成，不破解、不自动发外部通知。
- 用户明确表示已完成后重新观察页面，重新脚本检查全部筛选和 App，记录晚于 hold 的新日志，核对分页位置后执行 resume。不能用超时或旧截图替代用户确认和复核。
- 日期、地区、渠道、广告/素材模式、App或平台等条件改变时新建 run，不混用不同指纹的数据。
- 不调用私有接口、监听网络、读取隐藏应用状态、共享登录态或启动独立浏览器爬虫。普通文件工具仅用于获准的已观察媒体下载、本地抽帧、落盘、打包和状态检查；遵守环境限制。
- 默认只产本地结果；不自动写 VE/Arrow2/飞书、发消息、调用收费模型或复刻。全量仅指当前账号和筛选下站点可访问列表，不承诺平台真实广告全集。
