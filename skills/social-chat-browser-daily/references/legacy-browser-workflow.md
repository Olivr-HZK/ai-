# 浏览器备用流程：仅显式授权时使用

默认已改为插件下载后手动交接。本文保留历史浏览器采集/全量状态机与通知规则，不能用于普通ZIP交接。新建备用批次时prepare必须显式加 --collection-mode direct-browser-v1；历史目录仍按其固定scope恢复。以下旧“默认”文字仅描述该备用模式，不覆盖现行入口。

# 社交聊天竞品日采集

## 每日入选数量（2026-10-26）

新批在全部内容审核后，将视频与图片、所有竞品及双端合并，按展示估值降序取前100条，替代前10%；不足100条时取实际通过项并报告缺口，不降低内容/媒体标准、不用存疑或排除项补数。并列按完整App名/系统平台/App ID/广告ID稳定排序。prepare将config.ranking的top_n/count=100固定到scope；RANK、看板及日报使用该固定规则。历史批次恢复沿用原scope，无ranking字段时仍按旧前10%，不自动重排历史或改飞书。本次10月24日新口径复筛单独按用户要求取前100条，原严格审核与21条入表记录保留。

## 每日精选独立打包（2026-10-26）

审核和排名完成后，仅把实际入选素材单独打成ZIP，命名 `Afizzy_竞品精选_YYYY-MM-DD_N条.zip`：日期用本批目标日，N用实际入选数量，不足100不补数。视频和图片按同一全局排名编号，文件为“排名_App名_广告ID”，多图同排名归入一个文件夹；保留实际原文件格式和字节。包内附素材清单CSV、审核说明、快照展示估值、原版本风格标签和逐文件SHA256；不打包排除/存疑/落选素材、凭据或原始签名URL。

正式混合流程的 `social_chat_mixed_delivery` 自动生成ZIP和看板下载入口。既有插件审核批次在原审核/selection已完成校验后执行 `.venv/bin/python -m ua_workflows.social_chat_selected_package --run-dir <目录>`，只消费现有榜单、不替代审核/排名。仅支持标准混合选择结构或已审核插件视频结构；其他插件图片布局须先规范化实际全部原图，不能漏图冒充成功。结果写在delivery目录及package-receipt.json，必须确认CRC、全部媒体SHA256、数量与榜单相符后提供文件链接。相同结果重跑复用包，结果变化另存_v2等版本，保留旧包。零入选不生成虚假的100条包。打包不替代飞书附件读回或授权群日报，不自动恢复已停用调度。

## 当前内容规则：男性角色主体，排除真人和女性主体

后续统一执行[内容审核规则](content-review.md)，新批版本为`male-character-no-real-person-v1`。视频、图片均只保留未见真人且男性角色为明确主体的素材；任何真人（含非口播、剧情、影视/照片、手部、混剪片段）或女性主体均排除。男女混合、无明确男性主体、真人/AI无法判断的先待复核，不进入风格看板、排名或入表。明显AI/动漫/CG男性不因写实画风剔除；角色主体不等同于目标受众性别。删除“真人实拍”风格选项。

新审核记录`review_policy=male-character-no-real-person-v1`、`checks.real_person_presence`及`checks.primary_subject`；旧口播false或无真人标签不能认证男性主体。仅absent+male能keep；校验器拒绝缺字段、不确定及决定不一致。历史版本不自动迁移或改写；新版只用于后续新批，重审旧批须保留原证据并取得明确授权。

通过内容审核时同时打风格标签，执行上述内容审核引用的“同次审核填写风格标签”。新批固定`style_tagging=character-style-v2`，保留项必须记录`style_tagging_version/style_tags/style_reason`；沿用一个风格标签多选字段，使用日式漫画、韩式漫画、欧美写实等地域审美与画面风格组合；数字插画与3D角色分开，古装仅在画面依据中记录。风格不明确仅填待确认并说明依据；排除/内容待复核项不打正式风格标签。标签随排名、交付HTML及后续飞书多选字段“风格标签”同步并读回，缺标不通过。历史批次不自动补标。

## 默认采集模式（2026-10-22）

新prepare固定collection_mode=direct-browser-v1，每App由direct_session.mjs执行并以APP_COLLECTION_PENDING一次验收。采用本轮实测的浏览器直采：不依赖插件弹窗，参考插件逻辑批量读取详情原素材并去重下载。先读 `guangdada-browser-crawl` 的 [直采与并行下载](../../guangdada-browser-crawl/references/direct-collection.md)。一次组合核对筛选、综合 App ID回车及最新创意；同页最多10张连续点卡，正常只返回摘要；每页保存后即可交给最多3路下载队列，与后续点卡并行。保持现有统一状态机和校验，不把下载预取当作审核、排名或入表成功。

这是 `ua素材` 项目的业务流程，依赖项目脚本和已安装的 `guangdada-browser-crawl` skill。先定位含 `config/social_chat_browser_daily.json` 的项目目录；从其他目录调用时不能误用旧 VE 日更入口。

当前口径以 `config/social_chat_browser_daily.json` 为准；完整名单在 `config/social_chat_browser_competitors.json`：iOS 10项、Android 11项，按完整 App 名核对身份、分平台采集，已核实ID保存在 `config/social_chat_browser_app_ids.json`。目标日默认北京时间昨天，含义是**首次发现**；默认工具/素材，已核实分类覆盖写入task.category（Heyyyy iOS为游戏），视频和图片均采集，渠道、地区、文案语言、尺寸不限，采集后排除重投，视频和图片均排除真人和女性主体，仅保留明确男性角色主体。不沿用旧的日韩、9:16或受众女频条件。

1. 在项目目录执行 `.venv/bin/python scripts/run_social_chat_browser_daily.py prepare`，读取输出的 `browser-task.txt` 和 `scope.json`。历史日用 `--date YYYY-MM-DD`；断点恢复用相同目录。prepare 仅准备本地任务，不会爬取或写表。
2. 读取并使用 `$guangdada-browser-crawl`，通过当前环境授权的浏览器工具完成21项。日期设置后，通过综合搜索输入已核实App ID并回车提交，每次搜索都必须重新点击“最新创意”，即使它已选中。缺ID先用完整名发现核对，再按ID重搜。采集期间不按展示估值排序或阈值截断；全部拿齐后本地按估值排名。新模式使用直采与并行下载引用中的createDirectSession.start()/batch()/nextPage()/resume()。所有 App/筛选、逐卡和翻页仍需脚本读回、前后截图、逐App direct/complete.json及验收清单；出现验证码停下等待人工。不可调用项目爬虫 CLI、私有接口或共享登录态。

4. 采集期间按页把已观察原素材加入去重下载队列，不等21项全采完才下载；复用已校验文件、失败预算跨轮保留。所有 App 采集封账并按独立重投标签剔除后，对剩余视频补齐下载、脚本抽六帧并实际查看，写 reviews。若详情是 YouTube 原始外链而非可直接下载的视频源，主动按 `guangdada-browser-crawl` 的“YouTube 原始外链补全”流程使用 yt-dlp 补全，保存来源/日志/哈希后走同样的抽帧审核；失败保留待补全，不直接剔除或按零估值排名。新批按[内容审核规则](content-review.md)实际判断真人出镜及男性角色主体，写新版审核记录；真人或女性主体排除，混合/不明确待复核，不能仅用旧口播字段通过。抽帧是画面初筛，不宣称完整审听。
5. 混合目标日窗口批次执行 `.venv/bin/python -m ua_workflows.social_chat_mixed_window select --run-dir <目录>`。它会重新检查状态机、21项完整性、日期、审核及估值，所有竞品/双端合并排序，按展示估值降序取前100条，不足100条取全部通过项。估值缺失或目标日待复核不能按零跳过。

## 每日自动执行的缺失媒体处理

## 视频和图片同时采集（2026-10-19 最新用户要求）

每日任务读取config.media_types（视频、图片），不再用仅视频筛选。类型控件不选任何选项时自动显示“图片&视频”，每项App/平台只跑一次混合列表，共21项。只读检查类型选择为空及默认显示，若残留“视频”或“图片”选项才清除；不得分别勾选或切换两轮。每次App搜索后检查条件并重新点击最新创意，保存混合列表零结果或日期截止证据，逐卡识别实际素材类型。图片不沿用旧视频六帧检查：下载实际原图，验证格式/像素尺寸/解码/SHA256并实际查看；多图素材查看所有可获取图片，图片不能因没有六帧或不适用真人口播而被剔除。视频仍执行六帧及真人出镜筛选；静态图片记录审核方法original_image并执行同一真人出镜规则，多图逐图查看。

日报总数同时包含视频与图片，并分别播报两类的上新数和获取成功数，再报审核可用合计、口播排除、下载失败、前100条实际入表数及多维表链接。未完成的类型不能漏报或按零跳过。此前视频限定及仅视频日报规则以本节为准。

## 已验证的混合目标日执行入口

`social_chat_mixed_window` 独立校验21项实际混合列表、搜索后最新创意、逐卡身份和截图、逐页连续位置、首次发现截止卡，以及绑定实际查看看板的原图/六帧清单哈希；`social_chat_mixed_delivery` 每次重新验证后生成本地HTML，将视频/图片上传各自附件并逐字段读回。缺失媒体写 `missing_media.json`，包含 task_id、ad_id、reason、实际失败记录 failure 与 attempts 日志路径；已有有效媒体清单或待审核内容不能使用缺失例外。详情出现“试玩广告”且实际为HTML iframe、无图片和视频源时记录为范围外，不伪装成图片下载失败。

## 每日浏览器采集防睡眠与异常日志（2026-10-21）

项目内的 `ua_workflows.browser_collection_runtime` 只管理本地电源保护/日志，不访问广大大、飞书或付费接口。采集前执行 `.venv/bin/python -m ua_workflows.browser_collection_runtime start --run-dir <本批目录>`，必须返回 `active=true` 后才开始浏览器操作。每页操作前及至少每5分钟执行同命令的 `renew` 并核对 active；`status` 可只读检查，非活跃返回非零退出码。15分钟无续期自动释放，不能把过期视为仍受保护；继续前重新 start。完成、异常停止、用户暂停或验证码/人工等待时执行 `stop`，确认终止状态；恢复后重新 start。不使用无限期后台 caffeinate，prepare 的短暂进程保护不覆盖浏览器步骤间隔。

浏览器工具异常时，将真实 JSON（stage、app_id、page、card、error_type、message、已有 traceback、evidence_paths）通过 stdin 交给 `.venv/bin/python -m ua_workflows.browser_collection_runtime error --run-dir <本批目录>`。仅保存实际错误；工具不提供堆栈时省略 traceback，不推测接口返回或伪造调用栈。日志落在本批 runtime/，凭据和签名 URL 脱敏，权限600。浏览器步骤的日志依赖执行者记录；Python准备/校验/入表/通知命令由 collection_phase 自动记录异常并释放防睡眠保护。下载/抽帧工具失败同样记录实际工具错误与日志路径。

保护允许锁屏/息屏；不承诺唤醒尚未开始任务的睡眠电脑，也不覆盖手动强制睡眠、合盖或关机。此功能不新增收费请求、不改重试/筛选/群消息规则，不修改历史批次。

## 定时与手动任务的登录恢复（2026-10-21 最新授权）

定时触发的新批次prepare显式传`--execution-origin scheduled`；手动发起默认manual。scope保存本批实际execution_origin，不能用config.execution默认scheduled推断，也不在恢复时改变来源或日期。定时批次遇登录失效/其他设备登录/强制退出，先保存断点，调用`.venv/bin/python -m ua_workflows.social_chat_login_policy decision --run-dir <目录>`；auto_relogin时直接使用当前浏览器已保存凭据或项目.env既有账号正常重新登录，不先询问用户，不输出凭据，不读取/复制cookie，不为恢复登录盲目新开浏览器配置。每批最多2次正常登录尝试；凭据不可用、登录仍失败或预算耗尽则说明具体阻塞，不循环提交。手动任务先询问用户，明确授权后才登录。

任何验证码/安全验证优先级最高：立即停止操作，不点击/拖动/自动破解；保存截图和断点，进入WAITING_HUMAN并stop防睡眠租约，请人工处理。用户确认完成后重新观察页面、核对登录/筛选/唯一已选App/分页位置并恢复，不重复通知或已保存卡片。普通登录失效在定时任务中走RETRY_REQUIRED及自动重登恢复，不直接当作验证码等待人工。

登录每次实际尝试保存时间、authenticated及证据路径JSON，再执行social_chat_login_policy record --outcome success|failed|captcha --proof <相对run路径>。该脚本只记脱敏结果和耗时，不登录、不保存密码。若记录captcha，人工确认并核对页面验证码已消失后，以带scope_sha256/observed_at/captcha_visible=false/evidence_paths的新观察，执行clear-captcha --confirmation <实际用户确认> --proof <观察路径>解除验证码闸口；不能仅因超时自行解除。成功登录后仍须按每日状态机恢复证明校验，不以登录按钮点击代替成功。
