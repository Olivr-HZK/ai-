# 社交聊天竞品日采集

这是 `ua素材` 项目的业务流程，依赖项目脚本和已安装的 `guangdada-browser-crawl` skill。先定位含 `config/social_chat_browser_daily.json` 的项目目录；从其他目录调用时不能误用旧 VE 日更入口。

当前口径以 `config/social_chat_browser_daily.json` 为准；完整名单在 `config/social_chat_browser_competitors.json`：iOS 10项、Android 11项，按完整 App 名核对身份、分平台采集，已核实ID保存在 `config/social_chat_browser_app_ids.json`。目标日默认北京时间昨天，含义是**首次发现**；工具/素材，视频和图片均采集，渠道、地区、文案语言、尺寸不限，采集后排除重投，视频另排除真人口播。不沿用旧的日韩、9:16、男性角色、女频条件。

1. 在项目目录执行 `.venv/bin/python scripts/run_social_chat_browser_daily.py prepare`，读取输出的 `browser-task.txt` 和 `scope.json`。历史日用 `--date YYYY-MM-DD`；断点恢复用相同目录。prepare 仅准备本地任务，不会爬取或写表。
2. 读取并使用 `$guangdada-browser-crawl`，通过当前环境授权的浏览器工具完成21项。日期设置后，按已核实App ID搜索并选中正确广告主，每次搜索都必须重新点击“最新创意”，即使它已选中。缺ID先用完整名发现核对，再按ID重搜。采集期间不按展示估值排序或阈值截断；全部拿齐后本地按估值排名。所有 App/筛选、逐卡和翻页仍需脚本读回、前后截图、逐 App seal 清单；出现验证码停下等待人工。不可调用项目爬虫 CLI、私有接口或共享登录态。
3. 用户确认：**可见详情日期范围的起始日期就是首次发现日期**。仅取详情 `YYYY-MM-DD~YYYY-MM-DD` 的起点（亦支持 `～` / `至`）。保存 `first_discovered_date`、`first_discovered_source=detail_date_range_start` 和原始 `raw_text`。不凭列表筛选日期或旧 `first_seen` 字段推断；缺少详情日期范围时报告阻塞。已有原始详情可按此规则重新解析，不改写原文或伪造标签。
4. 所有 App 采集封账后，对全部原始视频下载、脚本抽六帧并实际查看，写 reviews。若详情是 YouTube 原始外链而非可直接下载的视频源，主动按 `guangdada-browser-crawl` 的“YouTube 原始外链补全”流程使用 yt-dlp 补全，保存来源/日志/哈希后走同样的抽帧审核；失败保留待补全，不直接剔除或按零估值排名。只有真人口播可因内容排除：`decision=exclude`、`checks.real_person_talking_head=true`；非口播为 keep/false，不确定为 review，需解决后再计算目标日排名。抽帧是画面初筛，不宣称完整审听。
5. 混合目标日窗口批次执行 `.venv/bin/python -m ua_workflows.social_chat_mixed_window select --run-dir <目录>`。它会重新检查状态机、21项完整性、日期、审核及估值，所有竞品/双端合并排序，按有效候选数的10%向上取整。估值缺失或目标日待复核不能按零跳过。
6. 执行 `.venv/bin/python -m ua_workflows.social_chat_mixed_delivery --run-dir <目录>` 生成本地看板及飞书待写入包，检查后执行同一命令加 `--apply` 写入 config 指定的表。必须带完整脚本路径；sync 会重新检查全部证据，不信任旧 selection.json。唯一键为日期/平台/App ID/广告ID；重跑更新，不重复添加；同日落选的旧记录改为“当前入选=false”，不删除历史。

用户已授权本流程写指定飞书表；不把此授权扩展到其他表；用户已另行授权本工作流在核实的测试群发送采集启动通知并@所有人，另已授权完成采集并核验写表后在同一测试群播报日报，不扩展到其他群或其他事件。2026-10-19 用户已要求每日早上自动执行，当前本聊天定时任务为北京时间07:00；以config中的执行方式和实际自动化配置为准，不重复创建任务。Feishu 凭据只读取项目 `.env`，不得输出或复制到产物。

最终提供目标日期、21项实际完成情况、有效候选数、全局入选数和表格链接；未全采、未审核或未写表时说明停在哪一步。全量仅指当前账号与筛选下可访问的广大大列表。

## 目标日窗口采集与只读筛选核对（2026-10-19 用户修正）

- 国家、渠道等不限条件只读确认；仅在有残留选项时操作清除。不为生成点击日志反复打开/点击空条件。切换 App 不重复触发这些控件；工具子分类也须只读确认不限，尤其不能误选“教育”。实际需要改变的条件、App搜索、排序、点卡与翻页仍保存真实操作证据。
- 按“最新创意”从新到旧逐卡检查：首次发现晚于目标日跳过，等于目标日采集，遇到第一张早于目标日的卡片即停止本 App 点卡与翻页。只读详情日期范围起点；单独首次发现旧日期不触发截止。保存截止卡 ID、页码/位置、日期、原文、点击日志和截图；截止卡只作边界证据，不进入目标日候选和抽帧队列。
- 新规则的完成含义是“目标日窗口采集完成”，不等于遍历网站全部卡片。可用独立目标日清单及证据校验报告封账；不得把旧版只支持 next_disabled/全部卡片计数的状态机强行写成通过。全局前10%仍需21项全部完成、目标日视频全部审核后计算。
- App ID 作为搜索关键词提交后，从“已选”标签核对实际查询 ID，再从每张详情官方商店链接或详情明确显示的 App ID + 平台核对身份。候选不存在或加载延迟不能误判零结果。

## 飞书字段约定（2026-10-19）

主列为 `appid`，值为实际 App ID；广告主（完整 App 名）、平台用单选，投放渠道、投放地区、文案语言用多选。保留视频附件与来源链接，不写“入选数量”“有效候选总数”“全局排名”三列；排名和候选计数仍保留在本地用于校验。后续写入保持此字段结构，不重新创建已删除的列。

## 每日自动执行的缺失媒体处理

用户要求沿用本轮流程每日执行：媒体有限重试仍无法获取时保存来源、失败原因及数量，单列跳过，在已审核可用素材中计算前10%，报告实际分母。此例外只适用于无法获取的媒体，不适用于未全采、App身份不明、缺估值或内容判断不确定。遇验证码或登录失效暂停请求人工，不能把整项采集失败当成零素材跳过。

飞书“来源”为单选，选项为“广大大”“facebookad libarary”“小红书”“抖音”；本工作流采自广大大，写“广大大”。来源与投放渠道是不同字段；即使媒体来自Facebook/YouTube，采集来源仍为广大大。

## 采集启动通知

每次prepare并固定目标日期后、实际浏览器抓取前，读取config.crawl_start_notice，使用项目广告之神应用向已核实的“霍振堃”测试群发一条启动通知并真正@所有人。执行 `.venv/bin/python -m ua_workflows.social_chat_crawl_notice --run-dir <本次目录>`；同批次恢复不重复通知。不在分享包内写入私有chat_id或凭据。测试用 `--test`，明确只测试通知、不重新抓取。发送回执、归一化@标记或UI证据核实后记状态；消息读取权限缺失不代表发送失败，不能因此重复@。

## 每日采集完成日报

在全部采集/媒体审核/前10%筛选及飞书实际写入验证后，由广告之神向config.crawl_completion_report配置的“霍振堃”测试群播报。执行 `.venv/bin/python -m ua_workflows.social_chat_crawl_report --run-dir <本批目录>`；首次测试加 `--test`，标注测试。播报目标日上新数、详情成功、视频成功、排除/缺失、审核有效候选数和前10%实际入表数，提供“查看多维表格”按钮。数字取证据和远端读回，不猜测；日期与统计范围明确。一个批次只发一次，保存稳定UUID及message_id；默认完成播报不@全体，启动通知仍按已授权规则@所有人。

## 视频和图片同时采集（2026-10-19 最新用户要求）

每日任务读取config.media_types（视频、图片），不再用仅视频筛选。类型控件不选任何选项时自动显示“图片&视频”，每项App/平台只跑一次混合列表，共21项。只读检查类型选择为空及默认显示，若残留“视频”或“图片”选项才清除；不得分别勾选或切换两轮。每次App搜索后检查条件并重新点击最新创意，保存混合列表零结果或日期截止证据，逐卡识别实际素材类型。图片不沿用旧视频六帧检查：下载实际原图，验证格式/像素尺寸/解码/SHA256并实际查看；多图素材查看所有可获取图片，图片不能因没有六帧或不适用真人口播而被剔除。视频仍执行六帧及口播筛选；静态图片记录审核方法original_image与真人口播“不适用”。

视频和图片审核可用候选合并按展示估值取前10%，向上取整，不分类型各取10%。原始记录、排名及入表须保留素材类型，图片上传为图片附件和实际链接，视频上传为视频附件；缺附件不冒充成功。旧state.py/select仅有视频六帧关卡，不能直接用它认证图片或混合任务；先补全并验证独立目标日混合媒体校验/入表适配，真实检查上述21项混合列表完成、日期、身份、原图/视频证据后再排名入表，不手改旧FSM通过。

日报总数同时包含视频与图片，并分别播报两类的上新数和获取成功数，再报审核可用合计、口播排除、下载失败、前10%实际入表数及多维表链接。未完成的类型不能漏报或按零跳过。此前视频限定及仅视频日报规则以本节为准。

## 已验证的混合目标日执行入口

`social_chat_mixed_window` 独立校验21项实际混合列表、搜索后最新创意、逐卡身份和截图、逐页连续位置、首次发现截止卡，以及绑定实际查看看板的原图/六帧清单哈希；`social_chat_mixed_delivery` 每次重新验证后生成本地HTML，将视频/图片上传各自附件并逐字段读回。缺失媒体写 `missing_media.json`，包含 task_id、ad_id、reason、实际失败记录 failure 与 attempts 日志路径；已有有效媒体清单或待审核内容不能使用缺失例外。详情出现“试玩广告”且实际为HTML iframe、无图片和视频源时记录为范围外，不伪装成图片下载失败。

同一批次的审核看板生成后不覆盖；后续下载成功的素材另建补充看板。`review_observations.json` 逐条记录实际查看的看板及SHA256、媒体manifest SHA256；视频记录 sampled_frames/frames_inspected/checks.real_person_talking_head，图片记录 original_image/images_inspected/全部 image_sha256s。真人情景短剧、仅出镜或AI角色说话本身不等于真人产品口播。

## 2026-10-20：按17号规则采集，采集后排除重投

用户确认17号口径正确。目标日期判断和首次早于目标日的截止只使用可见详情日期范围起点；独立“首次发现 (UTC+8)”字段仅留作原始证据，即使它更早也不提前停止，不作为日期范围的回退依据。每次App ID搜索后重新点击最新创意。重投卡片也正常点击、保存详情与截图，不因重投标记停止或在点卡阶段跳过。21项全部完成后，统一按详情可见独立“重投”标签排除，保留原始证据及剔除原因/数量；其余素材完成原图/视频审核、排除真人口播后，视频和图片合并取展示估值前10%向上取整。日报单列重投剔除数。历史批次不自动重写或重发。


## 每日浏览器采集防睡眠与异常日志（2026-10-21）

项目内的 `ua_workflows.browser_collection_runtime` 只管理本地电源保护/日志，不访问广大大、飞书或付费接口。采集前执行 `.venv/bin/python -m ua_workflows.browser_collection_runtime start --run-dir <本批目录>`，必须返回 `active=true` 后才开始浏览器操作。每页操作前及至少每5分钟执行同命令的 `renew` 并核对 active；`status` 可只读检查，非活跃返回非零退出码。15分钟无续期自动释放，不能把过期视为仍受保护；继续前重新 start。完成、异常停止、用户暂停或验证码/人工等待时执行 `stop`，确认终止状态；恢复后重新 start。不使用无限期后台 caffeinate，prepare 的短暂进程保护不覆盖浏览器步骤间隔。

浏览器工具异常时，将真实 JSON（stage、app_id、page、card、error_type、message、已有 traceback、evidence_paths）通过 stdin 交给 `.venv/bin/python -m ua_workflows.browser_collection_runtime error --run-dir <本批目录>`。仅保存实际错误；工具不提供堆栈时省略 traceback，不推测接口返回或伪造调用栈。日志落在本批 runtime/，凭据和签名 URL 脱敏，权限600。浏览器步骤的日志依赖执行者记录；Python准备/校验/入表/通知命令由 collection_phase 自动记录异常并释放防睡眠保护。下载/抽帧工具失败同样记录实际工具错误与日志路径。

保护允许锁屏/息屏；不承诺唤醒尚未开始任务的睡眠电脑，也不覆盖手动强制睡眠、合盖或关机。此功能不新增收费请求、不改重试/筛选/群消息规则，不修改历史批次。
