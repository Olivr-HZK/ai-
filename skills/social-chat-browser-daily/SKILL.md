# 社交竞品每日最新：插件下载 → 手动交接 → 审核交付

默认 `collection_mode=plugin-handoff-v1`、execution=manual。用户用插件完成每日最新素材下载，再在聊天交接目标日期及原始ZIP（可多包）。没有ZIP时等待交接，不登录/打开广大大、不点卡、不创建21项App采集状态，不因过去定时指令重启自动采集。读取[插件交接与后处理](references/plugin-handoff.md)。

1. 固定用户指定目标日；未指定且确实为昨天时才按北京时间昨天。原ZIP及包内唯一下载报告必须保留。prepare只做本地交接登记和ZIP结构/CRC检查，不认证日期、审核或飞书成功。
2. 实际读取报告并核对日期、采集结束原因、成功/失败/缺址/未勾选/重复及文件对应关系。同日多包合并去重，保留原页/位置/广告ID，明确重投先剔除，未见标签保持未知。仅对实际已取得的视频与全部原图审核，Playable不执行；不自动重采/补下载。
3. **先去重，后人工看图**：对全部已下载非重投素材先同App/系统日内CLIP去重（阈值0.9，每簇留展示估值最高者），再比对目标日前7个自然日历史。不要预先按旧内容审核结果删候选。使用[去重与联合审核入口](references/pre-review.md)固定队列，缺历史日期/向量/身份须留账，不能当作零。去重只用原封面或3%代理帧；不启动旧爬虫、OpenRouter、全量六帧人工初筛。历史规则不自动迁移。
4. **一次查看同时做三件事**：只对去重剩余项按实际产品及系统分组，核验视频完整解码、图片解码/尺寸/格式/SHA256后，准备一套3%/15%/30%/50%/70%/90%六帧并并列实际查看；同一次完成内容审核、[广告模板判断](references/content-review.md#按产品俯瞰模板与内容风格联合审核)和风格打标，统一记录content/template/style及画面依据。已有且源/参数/哈希一致的六帧复用，不为三个任务各抽一套、各看一轮；证据不足才放大/补帧/播放。图片同一次逐原图检查全部三项，不伪造视频六帧。内容要求男性有意义展示、女频恋爱/伴侣陪伴相关、无真人主持式产品推广口播，允许女性配角/手部/非口播真人恋爱剧情。内容或模板存疑暂不纳入。通过项同次按固定character-style-v2打标：日漫/韩漫分开、数字插画/3D分开，古装记依据，不根据App/语言/投放国猜风格。详细见[内容与风格规则](references/content-review.md)。
5. 联合审核结束后，确认同模板且内容合格的每组只留展示估值最高一条；仅画风/品牌版式相同不合并。视频与图片、双端合并按展示估值降序取前100条，不足取实际合格数，不用存疑/排除或前序去重项补数；并列按完整App名/系统平台/App ID/广告ID稳定排序。估值缺失不能当0。保留去重、联合审核、模板代表及排名逐项账；不冒充21项App完整日采集，不自动重算历史榜单/飞书。
6. 生成逐项审核清单、看板、入选榜单和独立ZIP。命名 `Afizzy_竞品精选_YYYY-MM-DD_N条.zip`，N为实际素材条数；包内“日期-序号-广告主.原格式”，多图同排名文件夹，附估值/风格/审核CSV、说明及逐文件SHA256。不转码、不带凭据/签名URL。已有已校验插件视频selection可执行 `.venv/bin/python -m ua_workflows.social_chat_selected_package --run-dir <目录>`；其他插件图片布局先规范化全部原图。核验CRC、原字节、数量、清单及排名；相同结果复用、变化另存版本。
飞书上传附件与ZIP内素材统一为`YYYY-MM-DD-序号-广告主.原格式`，日期用目标日、序号用最终入选排名且至少三位补零，例如`2026-10-26-001-Tipsy Chat.mp4`；多图末尾加`-01`、`-02`。广告主使用实际可见完整名称，文件系统不支持的字符替换为下划线，广告ID留在清单。使用`ua_workflows.social_chat_media_names.media_filename`统一生成名称，排名确定后再上传；插件后处理复用`social_chat_mixed_delivery.upload_selected`，按目标日/排名/广告主/原扩展名生成名称，缓存键包含文件名，不能复用旧名字的token。写表后用`verify_attachment_names`实际核对附件名与精确大小；不能只修改显示清单。历史文件/已入表附件本次不追溯改名。

7. 按已有授权幂等写config指定飞书表，实际上传视频/图片并逐字段读回、核对token和精确大小；主列“链接”写实际广大大详情URL（原“广大大详情”的内容），不写App ID或仅写“查看详情”；实际App ID保留在独立“App ID”列，未知留空，不按名称猜。平台广大大、来源每日最新；广告主/平台单选，渠道/地区/语言/风格多选。插件批次唯一键包含日期/源包摘要/广告ID等真实身份，保护其他批次、历史与手动记录。不将插件包送进旧浏览器mixed_window全采状态机，不伪造完成。

本地交接入口：

```bash
.venv/bin/python scripts/run_social_chat_browser_daily.py prepare --date YYYY-MM-DD --source-zip "/原包路径.zip"
```

多包重复传 `--source-zip`，或同目录继续交接；没有source-zip则返回WAITING_PACKAGE。有包且ZIP检查通过仅返回PACKAGE_RECEIVED，还须实际审核原报告与媒体。默认目录data/social_chat_plugin_handoff/YYYY-MM-DD，状态handoff.json，固定条件scope.json，下一步handoff-task.md。准备命令不抓取、不上传、不发群，不等同于后处理已完成。

用户已授权写指定飞书表，凭据只读取项目.env且不输出。插件交接不自动发“正在抓取”@全体通知，也不套用要求21项全采的旧日报。群播报如执行须有相应授权、反映实际交接包范围及远端核验结果，按真实回执去重。保留已停用任务状态，不重新创建定时任务。

最终给目标日期、交接包/实际媒体数、重投与失败/存疑/排除数、通过及实际入选数、精选ZIP和飞书链接；缺失或未执行如实说明。仅在用户明确要求直接浏览器采集或恢复旧浏览器批次时，读取[浏览器备用流程](references/legacy-browser-workflow.md)并使用guangdada-browser-crawl。旧scope/审核/排名/表记录不自动迁移。

## 2026-10-27 统一素材附件字段

所有实际入表视频、图片以及已有/明确允许入表的Playable原附件共用一个附件字段：字段ID `fldRHIjFcO`，当前名称 `竞品素材（图片/视频/Playable）去除男频`。写入前读取实际schema，按config.feishu.attachment_field_id匹配并核对附件类型17，再使用实际当前名称；本地预览可用config中的名称快照。不要重新创建旧“视频附件”“图片附件”列，也不能按素材类型把另一列清空。素材类型本身继续分别记录。Playable可存原HTML等文件但不得执行；统一附件字段不扩张原采集/审核/排名范围，不把Playable封面冒充已取得原文件。

插件批次将upload_selected返回的真实token写入上述同一字段，多图全部上传/保留，按实际字段读回token、名称、精确大小；verify/verify_attachment_names需要传实际字段名。旧分列附件迁移只能在明确授权下将原token与目标已有token有序去重合并，保留旧源列、复刻附件及其他业务字段，不能覆盖目标已有文件、改审核结论或批量重传。

主列字段当前ID为fldM60UZFW、名称“链接”、文本type1；后续不重建旧appid或广大大详情列。读取记录用text_field_as_array=true取得富文本内的真实link；“查看详情／按广告ID查看详情”可以只是有效超链接的显示文字，不能仅据普通文本读回认定URL丢失，更不能擅自回填覆盖。现有链接保留，新入表直接写真实详情URL；读回核验真实URL。
